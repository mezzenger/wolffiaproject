# Phase 2 roadmap

1. **Publication review and provenance.** Confirm the working identity, review scientific and food-safety claims against `docs/source-register.md`, recheck water-spinach rules, review recipe licensing and images, and resolve all `needs-review` and `placeholder` content intended for launch. Keep `do-not-publish` material out of `public/`.
2. **Human accessibility review.** Test keyboard order, menu behavior, visible focus, recipe filters and loading states, screen readers, 200% zoom, contrast, reduced motion, and touch targets. Record and fix findings.
3. **Contact and privacy decision.** Approve a private contact route, steward, retention practice, and host-specific privacy wording before inviting private submissions. Review the GitHub public issue handoff.
4. **Educational publishing pattern.** Pilot one reviewed, printable tutorial with source links, author/reviewer, review date, translation notes, and downloadable format. Use its lessons to decide whether structured metadata or a generator is warranted.
5. **Pilot and update process.** Define approval and redaction rules for measured results, failures, costs, and project updates before publishing any operational claim.
6. **Launch preparation.** Complete the launch checklist, cross-browser/mobile checks, performance review, approved domain/canonical metadata and sitemap, and an explicit indexing decision.

Recommended first task: conduct the claim, recipe, and media provenance review so the public draft has a clear publication boundary before adding new educational material.
